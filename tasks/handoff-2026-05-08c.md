## What shipped this session

### 1. Spam-prevention end-to-end (the big arc)

The session opened with "people can still sign up with no captcha" — a real
gap. Closed it across four layers:

- **`5dfd9d5` / `e751d6e` / `8717e07`** — Turnstile gate hardening
  iterated: hard-fail → reverted to soft-gate per Xero's call ("don't force
  ad blocker disable, maybe later"). Final state: when Turnstile produces a
  token, server-verify against Cloudflare. When it doesn't (ad blocker / no
  JS), fall through and rely on honeypot + `looksRandom` + Supabase's own
  CAPTCHA enforcement (when dashboard toggle is on). `captchaToken`
  forwarded to `auth.signUp` / `signInWithPassword` regardless, so the
  Supabase dashboard toggle is the eventual server-side gate.
- **`7d50527`** — Email-confirmation gate. New `app/auth/callback/route.ts`
  Route Handler. /signup detects `data.session === null` post-signUp and
  swaps to "Check Your Email" view with Resend button. /login surfaces
  "Email not confirmed" with Resend button as an amber banner (not the
  generic red error block).
- **`41040af`** — RLS error fix on signup. `supabase.from('profiles').upsert(...)`
  was failing with "new row violates row-level security" because email-
  confirm flow has no session yet (auth.uid() is null on the client). The
  `handle_new_user()` trigger handles profile creation server-side; client
  upsert moved to /auth/callback (where auth.uid() is non-null) as belt-
  and-suspenders.
- **`96579c5`** — Critical callback fix. Original route only handled OAuth
  PKCE `?code=<...>` shape, but Supabase email links arrive with
  `?token_hash=<...>&type=signup`. Different API: `verifyOtp({type, token_hash})`
  vs. `exchangeCodeForSession(code)`. Tested end-to-end with a fresh signup
  → email arrives via Resend → click link → `/dashboard` logged in. ✅

### 2. Resend SMTP wired into Supabase Auth

The chain that took the most clicks:

- Wix DNS doesn't support MX on subdomains (Resend needs `send.<domain>` MX
  for bounce handling). Worked around by migrating DNS to Cloudflare.
- **DNS migration:** Cloudflare added → existing records auto-imported →
  GoDaddy nameservers swapped to Cloudflare's `andrea.ns.cloudflare.com` +
  `max.ns.cloudflare.com` → status flipped to Active.
- **Hiccup:** Cloudflare's auto-scan missed `thetapestry.distemperverse.com`
  (the Vercel-hosted app subdomain), site went down for ~1 minute until we
  added the missing CNAME (`thetapestry` → `55d8fd44b8eaaed4.vercel-dns-017.com`,
  proxy DISABLED so Vercel's SSL works).
- **Resend domain verification:** added 4 records (DKIM at `resend._domainkey`,
  MX `send`, TXT `send` SPF, TXT `_dmarc` DMARC). All green.
- **Supabase Custom SMTP:** Authentication → Emails → SMTP Settings:
  - Sender: `noreply@distemperverse.com` ("The Tapestry")
  - Host: `smtp.resend.com:465`
  - Username: `resend`
  - Password: dedicated `re_...` API key named "Supabase Auth"

Cost: $0. Resend free tier (3k emails/mo) covers launch. Free Cloudflare
plan covers DNS forever. Supabase Custom SMTP is a free feature.

### 4. Security hardening pass

- **`ab7e2ff`** — `sql/security-hardening-2026-05-08.sql`. Single migration
  clearing ~120 of ~130 Supabase Database Linter warnings.
  - Tier 1.1 — `REVOKE EXECUTE FROM PUBLIC, anon` on
    `admin_users_with_login` + `admin_user_with_login`. Postgres' default-
    grant-to-PUBLIC made the redundant `GRANT TO authenticated` a no-op.
  - Tier 1.2 — Replaced 3 always-true RLS policies:
    * `sessions` INSERT — was `with_check: true`; scoped to GM
    * `sessions` UPDATE — was `using/with_check: true`; scoped to GM
      (matches the existing `sessions-rls-fix.sql` pattern)
    * `session_attachments` ALL — was `using/with_check: true`; split
      into 4 policies; SELECT open, writes scoped to `uploaded_by =
      auth.uid()`. Conservative — GMs lose ability to delete other
      members' attachments via this path. Add a `gm_bypass` policy if
      that turns out to matter.
  - Tier 2.1 — `SET search_path = public, pg_catalog` on every public
    function without one (idempotent DO block; ~50 functions).
  - Tier 2.2 — `REVOKE EXECUTE FROM PUBLIC, anon, authenticated` on
    every trigger function (return type `trigger`; ~30 functions). Safe
    because triggers run as their owner regardless of RPC EXECUTE perms.
