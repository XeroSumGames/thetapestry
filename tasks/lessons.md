# Lessons Learned

## Database & Auth
- **Role is now normalized to lowercase**: DB trigger `trg_normalize_role` auto-lowercases `profiles.role` on insert/update. All existing rows backfilled. Always compare against `'thriver'` / `'survivor'` (lowercase). No more `.toLowerCase()` needed — but harmless if left in.
- **Supabase email-confirmation links use `verifyOtp`, not `exchangeCodeForSession`**: confirmation emails carry `?token_hash=<...>&type=signup`, not `?code=<...>`. The latter is for OAuth/PKCE. A `/auth/callback` route built only for `code=` silently fails on every signup-confirmation click. Branch on which params are present and call the right API. Cost: an end-to-end signup test on 2026-05-08C produced "Invalid login credentials" because email never got marked confirmed.
- **Postgres grants `EXECUTE` to `PUBLIC` by default on every new function**: writing `GRANT EXECUTE ON FUNCTION foo() TO authenticated` is a no-op for security purposes — `anon` already had it via PUBLIC. To restrict: `REVOKE EXECUTE ... FROM PUBLIC, anon` first, then GRANT. Surfaced 2026-05-08C when Supabase linter flagged `admin_users_with_login` as anon-callable despite the grant.
- **Trigger functions don't need RPC EXECUTE permissions**: triggers fire from DB events and run as the function owner. Revoking EXECUTE FROM `public, anon, authenticated` on every trigger function in `public` is safe defense-in-depth and clears ~30 linter warnings in one shot. See `sql/security-hardening-2026-05-08.sql` Tier 2.2.
- **FK to `auth.users` defaults to `NO ACTION` if you don't specify ON DELETE**: meaning every `DELETE FROM auth.users` errors with FK violations on un-cascaded child tables. The whole DELETE rolls back atomically — partial deletes don't happen. Fix: audit every FK to `auth.users`, set ON DELETE CASCADE for owned data, ON DELETE SET NULL for community-contributed content (where row should persist with attribution cleared). See `sql/fix-auth-cascades-2026-05-08.sql` for the canonical 5-table fix.
- **`information_schema.constraint_column_usage` can hide cross-schema FKs**: the view sometimes doesn't surface FKs from `public.X` to `auth.users` even when they exist. For reliable FK introspection, query `pg_catalog.pg_constraint` directly (`pg_class`, `pg_namespace` joins). Burned ~10 minutes during the cascade audit.
- **Wix DNS doesn't support MX records on subdomains**: even when MX on root works fine. Resend's verification needs an MX on the sending subdomain (`send.example.com`) and Wix returns "this isn't supported" silently. Plan B: migrate DNS to Cloudflare (free, ~30 min). Cloudflare auto-imports existing Wix records before the swap; site stays up if all subdomains were registered (gotcha: Cloudflare's auto-scan can miss `thetapestry.distemperverse.com` style Vercel subdomains — verify the imported list before changing nameservers at the registrar).
- **RLS blocks everything by default**: When creating new tables, always add RLS policies immediately. Storage buckets need separate policies on `storage.objects` — the bucket existing is not enough.
- **Supabase Storage buckets must be created manually**: They don't auto-create from code. Each bucket needs INSERT/SELECT/DELETE policies on `storage.objects` filtered by `bucket_id`.
- **Column must exist before code references it**: Always provide the ALTER TABLE SQL alongside the commit. Don't assume the user has run previous SQL.
- **Every ALTER TABLE migration must end with `NOTIFY pgrst, 'reload schema';`**: PostgREST caches its schema introspection. If the cache predates the column, the API silently strips that column from write payloads — direct DB queries succeed, client updates "revert" on next read. Cost a debug session on 2026-05-04 (pin sort_order revert). Idempotent and cheap; add it unconditionally to every column-add migration.
- **Always `.select()` after `.update()` and check the error**: Fire-and-forget updates with optimistic local state hide RLS rejections, schema-cache misses, and constraint violations. Pattern: `const { data, error } = await supabase.from(t).update(u).eq('id', id).select().maybeSingle()`. If `error` or `!data`, alert and abort — don't repaint.

- **Null-coalescing chains can create false positives**: `npc.wp_current ?? npc.wp_max ?? 10` evaluates to `0` (and filters as "dead") when both fields are null. Only filter entities as dead when their health field has been explicitly set to 0, not when it's null/uninitialized. Use `npc.wp_current != null && npc.wp_current <= 0` instead.
- **Realtime subscriptions must match the events you need**: Subscribing to `INSERT` only means `DELETE` events are invisible to other clients. If a feature clears data (like session end deleting logs), use `event: '*'` so all clients see the change.

## React & Next.js
- **Emoji icons don't respond to CSS `color`**: Emojis render as images. Use SVG icons if you need color to change dynamically (e.g., notification bell).
- **`await` your Supabase calls**: Fire-and-forget (`supabase.from(...).update(...)` without `await`) causes race conditions. The Realtime subscription can fire before the write completes, reading stale data.
- **Optimistic state updates prevent stale reads**: When updating a value (like insight dice), update the local state immediately in addition to the DB write. Don't rely solely on Realtime to propagate changes.
- **Layout flash on conditional rendering**: If a layout element (sidebar) depends on async state, the page will flash/jump when that state resolves. Fix by either always showing or always hiding the element on that route, not conditionally based on async data.
- **`return null` during loading causes layout shifts**: Use `return <div style={{ background: '#0f0f0f' }} />` instead to maintain the DOM structure.

## Tactical Map
- **Tokens always spawn at top-left (1,1)**: All tokens (PC, NPC, objects) spawn at grid position (1, 1) — top-left of the tactical map. Never top-right. The GM controls strip is on the left but tokens go there anyway — the GM drags them to position. This was changed back and forth; top-left is the final decision.

## Client-Side Image Processing
- **Canvas center-crop pattern**: `const srcSize = Math.min(w, h); sx = (w - srcSize) / 2; sy = (h - srcSize) / 2` then `ctx.drawImage(img, sx, sy, srcSize, srcSize, 0, 0, OUTPUT, OUTPUT)` — crops to square from center before resizing. Set `ctx.imageSmoothingQuality = 'high'` for the downscale.
- **Quality slider live-update**: Keep the loaded `HTMLImageElement` in a ref so changing quality can re-run `processImage` without re-reading the file. A `useEffect([quality])` triggers re-processing only when quality changes.
- **File input re-selection**: After `onChange`, reset `e.target.value = ''` so the user can pick the same file again (e.g., after resetting state).
- **`<input type="file">` click-to-browse on drop zone**: Hide the input with `display: none`, use a ref, and call `fileInputRef.current?.click()` from the drop zone's `onClick`. Clicking anywhere in the zone opens the picker.
- **`canvas.toBlob` vs `canvas.toDataURL`**: `toBlob` is async and gives you the exact file size for display; `toDataURL` is synchronous and gives a string suitable for `<img src>` and `<a download>`. Use both in parallel when you need both size stats and a preview URL.

## Styling
- **Banned combo: `fontSize: '12px'` + `color: '#3a3a3a'`**: Use `13px` + `#cce0f5` instead. The pair is illegible on the dark theme even though each value passes its own guardrail. Applies site-wide — `node scripts/check-font-sizes.mjs` flags violations. Rule recorded in `AGENTS.md` under UI conventions.
- **Header buttons must all be the same size**: The campaign table header bar uses the `hdrBtn()` helper for uniform 28px height Carlito buttons (font size enforced by AGENTS.md inline-min-font rule, currently 13px). When adding new buttons to this bar, ALWAYS use `hdrBtn()` — never inline custom styles. This has been broken and fixed before. Check `hdrBtn` usage before adding any button to the header.
- **Carlito > Barlow Condensed for UI labels** (2026-04-29): Playtesters reported Barlow Condensed at 13px (the project minimum inline font-size) was too narrow to read on chips, badges, and small buttons. Whole-codebase swap to `'Carlito, sans-serif'` (open-source Calibri-equivalent webfont, loaded via Google Fonts) — 1,583 inline references across 91 files. Default new UI to `Carlito`; do not introduce new `Barlow Condensed` styles. Body text still uses regular `Barlow`. The sed swept the obvious inline form plus Leaflet popup HTML strings, canvas `ctx.font`, double-quoted variants, and escaped-quote innerHTML — if a new feature reintroduces `Barlow Condensed` via any of those forms, the legibility regression returns silently.

- **`#5a5550` is too dim**: This color was used as secondary text throughout the app but is nearly invisible on dark backgrounds. Replaced globally with `#cce0f5` (light blue).
- **Minimum font size is 13px**: Never use font sizes below 13px anywhere in the UI. The dark background makes small text unreadable. Badges/tags: 13-14px. Body text: 14-15px. Headings scale up from there. Multiple rounds of +2px bumps were needed across roll feed, session history, and NPC roster because initial sizes were too small.
- **`appearance: 'none'` on selects**: Required for consistent cross-browser styling of dropdowns.
- **Grid needs enough container width**: `auto-fill` grids won't show multiple columns if the parent container is too narrow (e.g., constrained by sidebar). Use fixed column count (`repeat(5, 1fr)`) when you know the layout.

## Architecture
- **Extract large features into components**: The table page was getting huge. NpcRoster, NotificationBell, and VisitLogger were extracted as separate components to keep the main page manageable.
- **Store structured data, serialize for display**: Skills are stored as `{ entries: [...], text: "..." }` — structured for programmatic use, text for backwards compatibility and display.
- **`SECURITY DEFINER` on trigger functions**: Required for triggers that insert into tables with RLS (like notifications), since triggers run as the invoking user who may not have insert permissions.

Load <relevant spec files> first.` Should reference the project-surviving files (tasks/todo.md, tasks/spec-*.md, tasks/rules-extract-*.md, tasks/testplan.md, tasks/lessons.md) so fresh-me has everything needed without re-litigating the last session. Load tasks/spec-communities.md and tasks/rules-extract-communities.md first.` Don't include stuff only meaningful in the current session (recent commit hashes, "we just shipped X"); stick to things fresh-me can actually reload.

## Process
- **Always provide SQL upfront**: When a feature requires a DB schema change, provide the ALTER TABLE / CREATE TABLE SQL immediately in the same message — don't wait for the user to ask. The user shouldn't have to chase for it. This is explicitly required in CLAUDE.md: "Always provide the ALTER TABLE SQL alongside the commit."

- **Provide all pending SQL in order**: When multiple features add columns/tables, the user may not have run earlier SQL. Always check and provide the full chain.
- **Debug logging is essential for remote debugging**: When the user can't see what's happening, add `console.log` with prefixed tags like `[EndSession]`, `[StatUpdate]`, then remove after diagnosis.
- **Test on the actual deployment**: localhost behavior can differ from deployed behavior (caching, env vars, auth state).
- **Verify the DB table/column exists before assuming code works**: A 400 error or silent null often means the schema doesn't match the code.
- **Supabase auth triggers must use EXCEPTION handler**: If a trigger on `auth.users` fails, Supabase rolls back the entire transaction including user creation, showing "Database error saving new user". Always wrap trigger INSERT in EXCEPTION WHEN OTHERS to prevent blocking signup. The client-side fallback code handles profile creation if the trigger fails.
- **CHECK constraints vs trigger values**: The `handle_new_user` trigger was inserting `'survivor'` (lowercase) but `profiles.role` has a CHECK constraint requiring `'Survivor'` (capitalized). Always match exact casing in trigger functions.

## 2026-04-11 session

- **Silent Supabase UPDATE failures under RLS are the #1 "feature looks broken but code looks fine" cause**: Supabase `.update()` returns `{ error: {...} }` without throwing. `console.warn('[tag] update error:', error.message)` is easy to lose in the noise. For writes that MUST land (combat state, action consumption, turn advance), check the `error` return AND think about whose client is making the call — if the write path runs on the player's client, RLS policies that allow only GM writes will silently drop every update. Nana bug: player attacks fired, roll logs landed, but `initiative_order.actions_remaining` never decremented because the player's client couldn't UPDATE the table. The symptom looks identical to "consumeAction isn't being called" but it's actually "consumeAction IS called, the UPDATE returns an error, we logged it once and moved on".

- **Pseudo-weapons sneak past `getWeaponByName` inference**: `Unarmed` (and anything else fabricated inline in the UI with `{ weaponName, damage, rpPercent }`) has no entry in `MELEE_WEAPONS` / `RANGED_WEAPONS`, so `getWeaponByName('Unarmed')` returns `undefined` and `isMelee = w?.category === 'melee'` falls through to `false`. That cascades: `rollDamage(..., !isMelee)` skips PHY AMod, and mitigation uses DEX instead of PHY. Fix the *inference*, not the damage pipeline — `isMelee = w?.category === 'melee' || weapon.weaponName === 'Unarmed'`. There was already a precedent at line 1481 special-casing `weaponName === 'Unarmed'` for Low-Insight weapon jams, so this has been stepped on before.

- **Label parsing is not a reliable way to identify the attacker**: `pendingRoll.label.split(' — ')[0]` works for NPC attacks (`Gio — Attack (Pistol)`) and consume-action logs (`David — Aim`), but breaks for PC weapon labels (`Attack — Crossbow`) where the first token is literally the word "Attack". Two separate bugs landed in the same week from this: (1) `roll_log.character_name` got the string `"Attack"` written into it, and (2) attacker-identity gating in `handleRollRequest` couldn't distinguish a known-name prefix from a generic action prefix. **Only trust `labelParts[0]` when it actually matches a known PC or NPC name** (check `entries` and `campaignNpcs`); otherwise fall back to `syncedSelectedEntry → myEntry`.

- **GM authority is the wrong escape hatch for turn-order gates**: The first cut of the combat gate let GMs bypass "is it this combatant's turn?" via `if (!iAmActive && !isGM) reject`. That let the GM click Attack on an off-turn NPC's NpcCard; the modal opened, the roll fired, `closeRollModal` then fetched `is_active = true` from the DB, which at that point was a *different* combatant, and consumed *their* action. The fix is to identify the attacker from label/context (NPC name from label, PC name from open sheet / current user) and require `attacker === active` *without* a GM override. GM still works via the `selectedEntry` branch (GM has the active PC's sheet open → attacker = that PC).

- **Postgres_changes on npc_relationships is flaky**: Subscribing to `postgres_changes` on `npc_relationships` with `event: '*'` does not reliably deliver updates to player clients — most likely the table isn't in the `supabase_realtime` publication, or RLS blocks the payload from reaching the player's channel. When the GM reveals an NPC mid-combat, the player's reveal list didn't refresh until a full page reload. Fix: send a `broadcast` event on a channel the player is already subscribed to (the `initiative_${id}` channel is a good shared bus), and have the handler refetch `campaign_npcs` fresh before calling `loadRevealedNpcs`. Broadcast events bypass RLS and publication settings entirely — they're peer-to-peer on the channel.
- **SECURITY DEFINER doesn't always bypass RLS in Supabase**: Despite documentation, trigger functions with SECURITY DEFINER may still be blocked by RLS policies. Add an EXCEPTION handler as a safety net.

## 2026-04-12 session

- **Cross-client state updates require broadcast, not just setState**: When a player deals damage to an NPC, `setCampaignNpcs`/`setViewingNpcs` only update the player's own React state. The GM's browser is a separate client and never sees the change unless Supabase Realtime fires (unreliable) or a broadcast event is sent. This is why NPC→PC damage worked (GM rolls, GM's state updates) but PC→NPC didn't (player rolls, GM's state stale).

No inline style overrides for sizing. The helper is defined at the bottom of `page.tsx`. This includes `<select>`, `<a>`, and `<div>` badges — not just `<button>`. If adding new controls to the header, use `hdrBtn()` and nothing else for the base style.

Use `boxSizing: border-box`. No exceptions.

A parallel agent shipped the same feature in the same window using `sort_order` — which is the convention every other ordering column in the repo already uses (`timeline-sort-order.sql`, `scene-tokens-sort-order.sql`, `modules-sort-order.sql`, `campaign-sort-order.sql`). One `ls sql/ | grep sort` would have caught it. Cost: a 3-conflict merge resolution and a rename across the component + alert + migration. That's a 6-file refactor that I'd unwind once one style is picked. Pragmatic move: write Style B with its own copy of the SRD content, ship the comparison fast, delete the loser in one commit. Duplication is bounded (only while the test runs) and it keeps the comparison's blast radius small.

## 2026-05-06 session

- **Sequence-guard pattern belongs in EVERY refetch hook, not just `loadEntries`**: `useRollsFeed.refetch` and `useChatPanel.refetch` had no defense against out-of-order completion — a slow earlier query landing AFTER a fast later one silently clobbered fresher state with stale data. The table-page's `loadEntries` has had `refetchSeqRef` since 2026-04-26; the rolls/chat hooks were left behind. Fix is mechanical: bump `++refetchSeqRef.current` at call site, capture the local seq, then `if (seq !== refetchSeqRef.current) return` after the await before any setState. **Rule:** any hook that exposes a `refetch()` and is called from realtime subscriptions or back-and-forth user input needs this guard. Symptom is hard to reproduce (only shows up under tight bursts) but easy to write — port the pattern eagerly when you spot a refetch without it. Commit `d4a97e1`.

- **`isGM &&` UI gates need to widen to `gmLike = isGM || isThriver` whenever RLS already grants Thriver write access**: The DB layer shipped `sql/thriver-godmode-policies.sql` weeks ago; Thrivers can write to every campaign at the RLS level. But `isGM &&` checks throughout the table page were excluding Thrivers from the matching edit affordances — RLS allowed the write, the UI didn't surface the button. Fix: derive `const gmLike = isGM || isThriver` once at the top of the component and route it through every `isGM={...}` prop pass + `gmTab === 'foo' && isGM` parent gate + `!isGM` player-branch fallback. Keep strict `isGM` only on identity-labeled surfaces ("GM View" button, "GM Tools" menu name) — Thrivers should still see themselves as themselves there, not impersonate the campaign GM. The DB-RLS / UI-gate parity is the actual bug class; check both layers when adding a new gated control. Commit `92f9243`.

- **`canEdit={true}` on a permission-gated component is a wide-open bug**: `VehicleCard` shipped with `canEdit={true}` hard-coded — every campaign member could edit shared vehicles regardless of role. Caught only because the godmode sweep audit walked every `isGM=` prop pass and noticed VehicleCard wasn't gated at all. **Rule:** when adding a new permission prop (`canEdit`, `canDelete`, `gmOnly`, etc.) to a component, default it to `false` at the component level and require the caller to widen explicitly with `gmLike` / `isOwner` / etc. Never default to `true`. When auditing existing components for a permission sweep, grep for `={true}` on the prop name first — it's the single fastest find for "the gate was never wired."

- **Inline editable surfaces work best as a small set of co-located helper components**: The GM Notes popout `c4610ad` made every field click-to-edit by introducing four helpers — `EditableText` (single-line + multiline, blur or Enter / Cmd+Enter to commit, Esc to cancel), `EditableSelect` (chip → dropdown), `EditableToggle` (boolean chip), `EditableNumber` (sort_order). Each does optimistic local update + rollback on `.update().select()` error so RLS rejections surface as alerts rather than silently dropping. Co-locating them at the bottom of the page file (rather than extracting to `components/`) kept the diff tight (~480 lines) and avoided the abstraction tax of "where does this live, what's the API surface" — they're shape-specific to this popout. **Rule:** when retrofitting click-to-edit onto a previously-read-only surface, write the helpers inline at first; only extract once a second surface needs them.

## 2026-05-08 session

- **`RETURNS TABLE (col ...)` shadows columns of the same name inside the PL/pgSQL body**: The new `admin_users_with_login()` RPC errored with `column reference "id" is ambiguous` the moment the page tried to call it. Cause: PostgreSQL's `RETURNS TABLE (id uuid, role text, created_at timestamptz, ...)` declares OUT parameters with those names. Any unqualified reference in the body — even in a subquery that doesn't touch the result set — collides with the OUT param and errors out. The `RETURN QUERY SELECT p.id, p.role, ...` was already aliased and fine; the bug was an unqualified Thriver gate `WHERE id = auth.uid() AND lower(role) = 'thriver'` reading from `public.profiles`. Easy trap because the qualified `RETURN QUERY` makes the function *look* safe. **Rule:** inside any PL/pgSQL function with `RETURNS TABLE`, every column reference in the body must be alias-qualified — including IF / EXISTS / subquery gates. Default pattern: alias the body's reads (`profiles caller`, `campaigns c`, etc.) so the OUT-param collision can't sneak back in. Alternative: `#variable_conflict use_column` at the top of the function. Commit `78df30c`.

- **A "missing" UI value is often a CSS-overflow bug, not missing data**: Xero reported "several users emails are still not showing" on `/moderate`. Audit found 15 of 16 profiles had `email`; only one was actually NULL. The other 14 emails were getting ellipsized off-screen behind long usernames because the row layout used `overflow:hidden + textOverflow:ellipsis + whiteSpace:nowrap` on a flex parent that crammed username + email + chips into one line. The "missing" emails were hiding in plain sight. **Rule:** when a user reports missing data on a list/table view, run a `count(*) total, count(field) present, count(*) - count(field) missing` query first to separate UI bugs from data bugs. Two minutes of SQL beats an hour of fixing the wrong layer.

- **"Not getting alerts anymore" is usually a stacked-gate suppression problem**: Visit emails went silent. Cause: `log-visit/index.ts` had two stacked gates — `isFirstVisit` (per session_id) AND `!isRepeatSurvivor` (signed-in users with `visitNumber > 5` were suppressed). Live data showed every active visitor's `ip_hash` count was in the 88–1612 range, so `isRepeatSurvivor=true` on every request → no emails fired anywhere. The suppression was correct in isolation; the *stacking* killed the channel. **Rule:** when an alert pipeline goes silent, check the actual production data against each gate independently — what fraction of recent events would each gate let through? If even one gate has a near-100% suppression rate, that's the dead one. Don't trust intuition about suppression rules drift; check the rows. Also: prefer one binary gate (here: `visitNumber === 1`) over two layered heuristics whenever the user's intent is binary ("only the first visit from a new visitor").

- **Process: write to `tasks/lessons.md` and `tasks/todo.md` IMMEDIATELY — never defer to "next time" or "if you want me to"**: I shipped a fix, mentioned the lesson worth keeping in chat, and signed off with "will add it next chance unless you'd rather I do it now." Xero corrected: "do it now, and WRITE IT DOWN that you should write stuff to LESSONS.MD and TODO.MD immediately, never wait for me to ask you to do it." The CLAUDE.md rule already says "After ANY correction from the user: update tasks/lessons.md with the pattern" — same applies after every meaningful ship, not just corrections. **Rule:** the moment a session produces (a) a correction, (b) a non-obvious bug fix worth remembering, or (c) a feature that should land in the shipped log, update `tasks/lessons.md` and `tasks/todo.md` in the same response. Don't ask permission, don't promise to do it later, don't bundle it into a "want me to..." offer. The user sees that as friction; they want the captures to happen as a reflex.

- **`app/globals.css` forces `select { width: 100% }` site-wide — inline `style={}` will not override it without an explicit `width`**: A `<select>` rendered with `padding/border/font` set inline but no `width` will silently stretch to the parent's full width because `app/globals.css:62` defines `input..., textarea, select { width: 100%; ... }`. React's `style={}` only sets the properties named — properties absent from the style object inherit the cascade, including the global `width: 100%`. Hit on the /moderate user-row redesign 2026-05-08 — the SUSPEND dropdown filled the bottom row, pushing DELETE to its own line. Fix: add `width: 'auto'` (and `flexShrink: 0` if inside a flex parent so it doesn't collapse) to the inline style. **Rule:** whenever you place a `<select>` in the codebase, default to setting `width: 'auto'` (or a fixed value) inline. The global rule was intentional for full-width form fields but is the wrong default for inline action-bar selects.

- **A lone flex item that wraps to its own line fills the full row width even with `width: auto`**: When a flex container uses `flex-wrap: wrap`, an item that ends up as the sole item on a line stretches to `flex-grow: 0, align-self: stretch` — and without explicit width it matches the container. Counterintuitive, because `width: auto` "should" shrink-to-content. The fix is never to let the two things that must stay together be separate flex children; wrap them in an inner `<div style={{ display:'flex', gap:'...', flexShrink:0 }}>` so they're always a single flex item from the parent's perspective. Hit on /moderate: Suspend select + Delete were separate children; when they wrapped they each tried to fill the row.

- **Cloudflare Turnstile Managed mode must NOT call `execute()` on submit**: Turnstile's Managed mode auto-solves the widget invisibly as soon as it renders. Calling `ts.execute(widgetId)` after that conflicts with the Managed solver and hangs indefinitely (the promise never resolves, the button freezes at "Verifying..."). The correct pattern: capture the token in the `callback` into a `useRef`, then read the ref on submit. If the ref is empty (very fast submit before solve finishes), set up a one-time override on the callback ref and call `ts.reset()` to re-trigger auto-solve, with an 8 s timeout. Never call `execute()` when the widget is in `size: 'invisible'` Managed mode.

- **Turnstile fail-open strategy: widget errors pass through, server token rejection is a hard block**: Turnstile widgets can error (error code 400020 = domain not registered, ad blocker, CDN issue). If a widget errors, `cachedTokenRef` is null — blocking on a null token would lock out real users whose browsers happen to have ad blockers or who are on localhost. Instead, track widget errors in a `widgetErroredRef`; when token is null AND widget errored, skip the Turnstile check entirely and fall through to signup (fail open). Honeypot + username consonant-run check are the first-line defense in this case. Only hard-block when the server explicitly returns a non-OK response to a token that was actually returned — that means the token was forged or reused.

- **Cloudflare Turnstile hostname management does not accept wildcards in the UI**: The "Add a custom hostname" field rejects `*.vercel.app` with "Enter a valid domain". Use the parent domain without the asterisk — `vercel.app` covers all subdomains. Register `localhost`, `thetapestry.distemperverse.com`, and `vercel.app` to cover all three environments (local dev, Vercel preview, production). No Vercel redeploy is needed after adding hostnames; Cloudflare propagates within minutes.

- **Leaflet: always call `map.remove()` in the `useEffect` cleanup**: Without it, navigating away from a page that renders a Leaflet map leaves an orphaned instance. When the component remounts (navigate back), `L.map(el)` finds a pre-existing `_leaflet_id` on the DOM element and throws `TypeError: Cannot read properties of undefined (reading '_leaflet_pos')`. Pattern: `return () => { if (mapRef.current) { mapRef.current.remove(); mapRef.current = null } }`. Also: always pass `minZoom` and `maxZoom` to `L.map()` init options — omitting `maxZoom` triggers a "Map has no maxZoom specified" console warning that becomes Sentry noise at scale.
